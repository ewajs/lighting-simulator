# 0050. Surface textures from a host provider, brightness matched to reflectance

- **Status:** Accepted
- **Date:** 2026-10-13

## Context

Room surfaces had a colour and a reflectance ρ only. Real projects are shown
with real finishes: oak floors, tiles, brick. A photo has its own brightness,
set by whoever took it. Drawn as it is, a floor could look like ρ = 0.5 while
the inter-reflection estimate (SPEC §6, ADR 0028) uses 0.3, so the picture
and the numbers would disagree.

## Options

- **Which surfaces:** room surfaces only / furniture finishes too
- **Where images come from:** a host provider, like IES files and models, with
  CC0 photos in the demo / textures generated by core / photos bundled in core
- **Maps:** colour only / colour, normal and roughness
- **Brightness:** the photo as it is / scaled to the surface's ρ
- **When a texture is on:** the colour tints it / the colour is set aside

## Decision

- **Room surfaces only.** Furniture finishes are built into core
  (ADR 0047), so textures for them would need a different source; that's a
  later step if wanted.
- **A host provider.** `Surface.texture` is an optional texture id, saved
  with the scene. `TextureProvider.load(id)` returns `{ data, widthM,
  heightM }`: a JPEG or PNG, and how much of the surface one copy covers.
  Core never fetches and ships no images. The Simulator loads each texture
  once (`simulator.texture(id)`, `onTexture`), like photometry and models.
  Those three caches are now one `AssetCache` with a small description per
  kind (`PHOTOMETRY_ASSET`, `MODEL_ASSET`, `TEXTURE_ASSET`).
- **The demo's materials are CC0 photos from ambientCG:** oak planks, stone
  tiles, white tiles, concrete, plaster and red brick, at 1024 px, 664 KB in
  total. `apps/demo/public/textures/SOURCES.md` lists each source.
- **Colour maps only.** A third of the bytes. Depth detail matters little on
  a floor seen from a few metres; normal maps can come later.
- **Brightness follows ρ.** The renderer measures each photo's average
  linear luminance once, on a 256 px copy, and multiplies the texture by
  ρ / average. The grain and colour variation stay, and the average albedo
  equals the ρ the lighting uses. The reflectance slider then makes a
  material lighter or darker.
- **A texture sets the colour aside.** Tinting a photo rarely looks right.
  In the room panel, picking a material sets its texture and its typical ρ,
  and the colour picker gives way to the material's swatch. Picking a
  colour takes the texture off. The host lists materials in
  `DisplayCatalog.materials`: id, name, swatch, typical ρ, and the surfaces
  each suits.
- **Real size.** Each face's UVs are its size in metres divided by the
  texture's, so planks keep their size in any room. Images repeat along
  the face's width and height, with no rotation or offset.
- **Clay mode** stays plain grey, with no textures.

## Consequences

- New public API:
  - core: `Surface.texture`, `TextureImage`, `TextureProvider`,
    `SimulatorOptions.textures`, `Simulator.texture`, `onTexture`,
    `TextureListener`;
  - UI: `DisplayCatalog.materials`, `SurfaceMaterial`.
- Old scenes load unchanged, since a surface without `texture` is as before.
- The demo's starter floor is oak planks, so every 3D screenshot changed.
- A texture that fails to load or decode logs a warning, and the surface
  shows its colour.
- Bright photos scaled up can push single texels past an albedo of 1. Only
  the average is physical; that's what the lighting uses.
- Not done: textures on furniture, rotating or offsetting a texture,
  uploading your own image.
